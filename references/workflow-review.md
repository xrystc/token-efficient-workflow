# Workflow review

Use a read-only, scoped review unless the user authorizes changes. Identify the unit of work and concrete evidence before recommending changes. Record what was observed separately from hypotheses; examples include repeated full-document reads, large tool outputs, repeated queries without an index, duplicated processing, overlong handoffs or overlapping delegation. File counts and the existence of versions alone do not establish waste.

Prioritize by likely frequency and avoidability, expected impact, implementation effort and effect on quality. For each recommendation specify the current evidence, proposed change, a verification check and uncertainty. Preserve necessary full-text reading, explicit user requirements, sample-dependency checks and reproducibility. Estimate impact only with comparable measurements.

Useful research checkpoint fields: objective; inclusion and exclusion rules; source IDs and current versions; study/participant/effect units; completed vs pending work; unresolved evidence; output paths; next action. Keep private project content out of reusable skill files and public examples.
